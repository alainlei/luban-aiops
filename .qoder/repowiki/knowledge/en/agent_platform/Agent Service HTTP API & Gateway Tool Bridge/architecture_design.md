Two cooperating sub-packages under `agent_service`:

- `api/` — FastAPI routers. The package root is a thin marker; the active surface lives in `api/v2/routes.py`, which mounts an `APIRouter(prefix="/api/v2")` exposing `/chat`, `/chat/stream`, `/chat/confirm`, `/chat/pending-confirmation`, `/sessions`, and session CRUD. Route handlers are pure adapters: they parse headers (`X-User-ID`, `x-request-id`, forwarded `Authorization: Bearer`), validate via Pydantic schemas from `agent_service.schemas.v2`, then delegate to domain services under `agent_service.services.*` (session store, confirmation registry, model catalog, authoring trace, evidence store, execution recovery, skills client, etc.). No AgentScope types leak through route signatures or response bodies.
- `tools/gateway_tools.py` — Bridges the runtime kernel to the external tool-gateway. It discovers tools via GET `/api/v2/tools` and invokes them via POST `/api/v2/tools/invoke`, wrapping each as an AgentScope `FunctionTool`. Read-only tools call the gateway directly; mutating tools (`risk_level != "read"`) first verify arguments against a signed execution envelope (`_verify_execution_request`) and then hand off to either the durable v3 coordinator (`_invoke_v3`) or the legacy worker (`_handoff_execution`).

Dependency direction is one-way: `api` depends on `services.*`; `tools` depends on `services.execution_*` and `services.kernel_middleware` only at call time (lazy imports) to avoid circular imports. Cross-cutting state (delegated bearer token, chat session id, execution request envelopes, current call id, generation owner) is threaded through `contextvars.ContextVar`s set by the runtime kernel around each turn, so cached toolkits survive portal token refresh without leaking credentials between sessions.
