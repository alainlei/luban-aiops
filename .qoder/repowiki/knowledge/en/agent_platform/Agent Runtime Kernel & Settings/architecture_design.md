Three cooperating files form the kernel boundary around AgentScope:
- `runtime_settings.py` defines a frozen `@dataclass` `RuntimeSettings` loaded from `AGENTSCOPE_*` / `AGENT_*` env vars via `_optional_*` helpers; `__post_init__` validates every knob (ranges, timezone, cross-field invariants like admission requiring DSN+epoch) and dispatches provider-specific option types (`DashScopeOptions`, `DeepSeekOptions`, `OpenAIOptions`).
- `runtime_kernel.py` exposes `AgentKernel`, which caches per-session `agentscope.agent.Agent` instances in an LRU `OrderedDict`, builds model/toolkit/middlewares on demand, persists/restores `AgentState` via `AGENT_STATE_STORE`, streams SSE frames through `StreamingProseRedactor`, and wires optional features lazily (execution recovery, compression tool, tracing middleware, reply budget).
- `services/kernel_middleware.py` implements three `MiddlewareBase` subclasses consumed by `_build_middlewares`: `GatewayPermissionMiddleware` enforces the platform's vetted allow-list (deny-by-default, with ASK parking for HITL), `ToolEvidenceMiddleware` emits SPEC-011 tool_call/tool_result frames into a request-scoped `ContextVar` sink, and `TokenUsageMiddleware` records provider-reported token counts as metrics. Cross-cutting state between them flows through module-level `ContextVar`s (`TOOL_EVIDENCE_SINK`, `STREAM_PENDING_DELIVERIES`, `PENDING_RELEASE_DELIVERIES`, `RELEASE_PERMITS`) set by the kernel around each streamed turn.
Dependency direction is one-way: kernel imports settings + services; middleware only depends on agentscope primitives and shared service singletons — never back onto the kernel except via contextvars.
