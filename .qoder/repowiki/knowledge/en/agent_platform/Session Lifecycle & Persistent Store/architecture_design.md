Three-layer split inside the module:
- `session_service.py` is the public API surface (`create_session`, `ensure_session`, `list_sessions`, `rename_session_title`, `mark_session_turn`, `pin_session_model`, `delete_session`). It owns business invariants (404-for-foreign-owner anti-enumeration, 50-session list cap, 80-char title cap, fail-open for non-critical bookkeeping) and orchestrates cross-store cascades on delete (agent state, evidence, confirmation records, execution records, authoring traces).
- `session_store.py` defines a `Protocol`-based `SessionStore` interface and ships three backends — `InMemorySessionStore`, `RedisSessionStore`, `PostgresSessionStore` — selected at runtime by `SESSION_STORE_BACKEND` via `build_session_store()`. Postgres is the durable backend (SPEC-016), Redis is the legacy cache-backed path, memory is dev/CI plus the fail-open fallback. The Protocol deliberately exposes no setter for `session_type`, enforcing it as a birth-only property.
- `session_transcript.py` is an independent best-effort reader that pulls `AgentState.context` snapshots, flattens block-structured content to chat text, and applies credential redaction before returning `(transcript_available, turns)`.

Dependency direction: service → store protocol + external stores; transcript → agent_state_store only. Backends depend on neither the service nor the transcript layer. Backend selection is driven by env vars (`SESSION_STORE_BACKEND`, `SESSION_TTL_SECONDS`, `SESSION_MAX_ENTRIES`, `SESSION_REDIS_*`, `SESSION_DB_URL`) with Postgres unavailable falling open to memory.
