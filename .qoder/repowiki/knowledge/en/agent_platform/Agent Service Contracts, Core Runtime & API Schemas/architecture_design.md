Three sibling sub-packages with a one-way dependency direction: `schemas/` depends on `core/`, while `contracts/` is pure data (JSON Schema + SQL) consumed by other services.

- `contracts/`: versioned JSON Schema files (`execution-request.schema.json`, `execution-receipt.schema.json`, `execution-observation.schema.json`, `execution-handoff-response.schema.json`, `execution-recovery.schema.json`, `tool-result.schema.json`) plus `execution-ledger-v1.sql`, forming the durable execution-lifecycle contract shared between agent-service and audit/service consumers. No Python code lives here.
- `schemas/`: Pydantic `BaseModel` definitions for the HTTP surface. `api.py` holds the legacy `/api/` models; `v2.py` is the single source of truth for `/api/v2/`, validated against the JSON Schema files in `shared/shared-contracts/schemas/`. Cross-type validation uses Pydantic `model_validator(mode="after")` (e.g. `DocumentCreateRequest`).
- `core/`: framework-agnostic runtime primitives. `config.py` exposes `get_settings()` via an `lru_cache(maxsize=1)` over `RuntimeSettings.from_env()`. `env.py` provides `get_env_value` / `get_env_int` fallback helpers. `request_context.py` resolves the `x-request-id` per SPEC-005 R-4 (inbound header → active OTel trace_id → generated UUID). `observability.py` configures root logging and emits structured JSON events. `metrics.py` registers prometheus_client counters/gauges/histograms behind RED middleware at `GET /metrics`, and mirrors every family to OTel via `MetricsMirror`. `telemetry.py` implements the opt-in OTLP push pipeline gated by `OTEL_ENABLED`, with lazy initialization, fail-open error handling, and a log bridge that keeps stdout JSON as the audit-truth source.
