The directory is a Kustomize overlay tree consumed by the `dev-k8s` deployment layer. It separates concerns into three sibling profile directories:
- `default/` — the active LLM provider profile; declares a committed non-secret `ConfigMap` (`agent-platform-runtime-profile`) plus local secret files (`runtime-secrets.env`, `runtime-secrets.example.env`) that feed the multi-model catalog (SPEC-026).
- `mutating-dev/` — not an LLM profile but a dev-only posture (SPEC-022 R-3) exposing pod-delete RBAC and setting `GATEWAY_MUTATING_TOOLS_ENABLED=true` via `mutating.env`.
- `browser-dev/` — also not an LLM profile (SPEC-049 R-7); ships the Chromium headless sidecar's NetworkPolicy and `browser.env` with `GATEWAY_BROWSER_*` knobs.

Each subdirectory has its own `kustomization.yaml` listing only resources it owns; strategic merge patches (e.g. `tool-gateway-browser-sidecar.yaml`, `tool-gateway-pod-delete.yaml`) are intentionally excluded from `resources:` because they are applied by the parent `dev-k8s` overlay where the Deployment target lives. The README documents that `dev-k8s` permanently wires `mutating-dev` and `browser-dev` alongside exactly one selected LLM profile, so these postures survive profile switches via `select-runtime-profile.sh`. Secret injection follows a dual path: CI can supply `agent-platform-runtime-secrets` directly, or locally `runtime-secrets.env` is used as a git-ignored fallback.
