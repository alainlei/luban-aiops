Flat index of one directory per specification under `docs/specs/`, each following the three-file template in `docs/specs/templates/` (`spec.md` for requirements + acceptance criteria, `plan.md` for technical approach, `tasks.md` for execution tracking). The root `README.md` defines the three-tier documentation model (Architecture Record / Feature Specs / Living State Docs), the required status lifecycle (`draft` → `approved` → `in-progress` → `delivered` → `superseded`), numbering/naming conventions, and the enforcement rules tying specs to PRs, tests, and `make verify`. Most specs are self-contained; cross-spec dependencies are expressed inline via `extends SPEC-NNN…` references in the spec index table. A few multi-part specs (e.g. SPEC-063 crash-safe execution with its own `failure-test-matrix.md` and `s6-acceptance-authorization.md`) nest additional artifacts inside their directory. There is no build system or executable code — this module is purely a human-readable decision and requirement registry consumed by reviewers and release managers.
