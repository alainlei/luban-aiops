The repository is organized as a product-oriented monorepo: `products/` holds independently built services (agent-platform, identity-broker, platform-gateway, tool-gateway, audit-service, execution-runtime, incident-service, skills-hub, operator-portal), `shared/` carries cross-cutting assets (`shared-contracts` for API/event/policy schemas, `platform-ops` for Kustomize overlays/dashboards/e2e scripts, `base-images/base-uv` for the Docker base image), and `docs/` contains ADRs, per-SPEC plan/spec/task triplets, release notes, guides, and workspace spikes. The root `Makefile` is the single orchestration point: it delegates per-product build/test/lint to each `products/<name>/Makefile`, aggregates them into coordinated container tags written to `shared/platform-ops/gitops/dev-k8s/.images.env`, and runs cross-cutting gates (kustomize overlay rendering, dashboard validation, policy bundle sync/validation, version lockstep, secret-vocabulary checks, portal Vitest + tsc build, execution failure test). Dependency direction is inward from products to `shared/shared-contracts` and outward via HTTP/gRPC APIs; there is no shared Python package dependency between products — coupling is contract-based. `mk/{defaults.mk,image.mk,python.mk}` centralizes overridable build knobs (IMAGE_PLATFORM, BASE_UV_* versions, KIND auto-load) so root and per-product invocations resolve identically.
