The service is assembled in `app.py` (`create_app`) which wires FastAPI lifespan, request logging, Prometheus metrics, OTel telemetry, and the v2 router; it never holds domain state itself. All cross-cutting concerns flow through shared singletons exposed by `core/` (`RuntimeSettings`, env, request-id context, metrics, observability) and consumed uniformly by every child:
- `api_layer` routes requests into `runtime_kernel.AgentKernel`, which owns AgentScope agent lifecycle, toolkit composition, streaming turns, evidence persistence, and prose redaction.
- `runtime_kernel` composes children: it instantiates `model_providers` adapters via `get_provider`, pulls tools from `tools/gateway_tools` (the platform tool bridge), persists state through `session_management`'s `AGENT_STATE_STORE`, records audit/evidence through `execution_orchestration` stores, and gates mutating calls with `flow_approvals` / `hitl_confirmations`.
- `contracts_and_core` provides the JSON Schema contracts and Pydantic models that both the API layer and kernel middlewares validate against.
- Background model discovery runs as an asyncio task during FastAPI lifespan, driven by `services/model_catalog` + `services/model_discovery`.
- The entrypoint split (`native.py` for direct AgentScope invocation, `runtime.py` for the HTTP process) lets the same kernel run inside or outside the web server.
