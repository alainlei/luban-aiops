- Configuration is modeled as frozen `dataclass`es parsed from `SKILLS_*` environment variables with dedicated `parse_*` helpers that raise `SettingsError` on malformed input, cached via `@lru_cache(maxsize=1)`.
- Backend selection uses a `Protocol` (`SkillStore`) plus a factory function (`build_skill_store`) that returns an in-memory implementation for dev/test and a Postgres implementation for production, keeping query logic backend-agnostic.
- Database migrations are expressed as idempotent SQL strings (`CREATE TABLE IF NOT EXISTS` followed by `ALTER ... ADD COLUMN IF NOT EXISTS` per spec version) executed during store initialization rather than via a migration tool.
- Validation functions return a discriminated result — either a validated payload or a `Rejection(source_id, path, reason)` tuple — instead of raising exceptions, so ingestion can collect all document failures without aborting.
- Route handlers follow a uniform shape: authenticate via `authenticate_caller`, validate parameters against module-level `MAX_*` constants, delegate to the store, emit usage audit events through `_emit_usage`, and return a typed `JSONResponse` built by `_error(status_code, code, message)`.
- Cross-cutting concerns (logging, metrics, telemetry, request-id propagation) are wired once in `app.create_app()` via FastAPI middleware and `setup_*` helpers in `core/`, never imported inside route handlers.
