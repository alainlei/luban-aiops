- Connectors are registered lazily inside `_build_tool_registry` under an `if settings.<feature>_enabled:` guard, importing the connector module only when its feature flag is true so disabled features incur no startup cost.
- Each connector exposes a `register_tools(registry)` method that instantiates concrete `BaseTool` subclasses and calls `registry.register(...)` with a `ToolDefinition` carrying `risk_level` (`read`/`write`/`admin`) and optional `extra_required_actions`.
- Policy decisions flow through `evaluate(settings, roles, action)` in `policy_engine.py`; every deny path records a metric via `record_policy_decision`, emits a structured audit event via `emit_audit_event`, and returns `make_denied_result` rather than raising exceptions.
- Identity is always derived from the verified bearer token header; any body fields like `session_id` or `approval_kind` are accepted only as trusted correlation hints after type/value validation and carry no authority.
- All tool results pass through `redact_result` at the single invoke choke point before response and audit emission, with overflow detected via `stats.overflow(fraction)` returning a `REDACTION_OVERFLOW` error instead of leaking credentials.
- Audit events are built with `build_audit_event` and emitted via `emit_audit_event` using the same shape (`event_type`, `request_id`, `status`, subject/actor/roles/details) across policy denials, tool invocations, and secret deliveries.
