This module is a documentation-only leaf under `docs/specs/` containing three sequential, cross-referenced spec packages — each a self-contained trio of `spec.md`, `plan.md`, `tasks.md`.

- SPEC-005 establishes the foundational two-surface contract: an always-on `GET /metrics` pull endpoint (RED + security-arc domain counters via `prometheus_client`) plus an opt-in `OTEL_ENABLED`-gated OTLP push pipeline to Elastic APM, bridging `x-request-id` to W3C `trace_id`. It defines the shared conventions doc in `shared/shared-contracts/observability-conventions.md` as the single reference for metric naming, label sets, and correlation rules across all services.
- SPEC-011 extends the tool-gateway with an Elastic observability connector (`elastic.search_logs`, `elastic.get_service_health`, `elastic.get_active_alerts`) and augments the agent-stream contract (`agent-stream-event.schema.json`) with `tool_call` / `tool_result` events so the operator portal can render an evidence panel alongside streamed text deltas.
- SPEC-065 closes R5 by emitting a first-class `agent_llm_tokens_total{provider,model,direction}` counter on the kernel's supported `on_model_call` hook, mirroring domain metrics onto OTel instruments via a parity-guarded bridge in `core/telemetry.py`, shipping OpenObserve dashboard config-as-code under `shared/platform-ops/`, and wiring a gated live-check script against the external `deepseek-v4-flash` provider.

Dependency direction is strictly forward: SPEC-065 builds on SPEC-005's two-surface contract and SPEC-011's connector/stream patterns; there are no code dependencies between the three directories — they are linked only by cross-references in their `spec.md` bodies and by the living-state docs they collectively update.
