Three independent spec directories under `docs/specs/`, each following the project's plan/spec/tasks triad:
- `SPEC-013-durable-audit-trail/` defines the foundational layer: a canonical `audit-event.schema.json` in `shared/shared-contracts`, an `AuditStore` protocol with `memory`/`postgres` backends selected via `AUDIT_STORE_BACKEND`, fire-and-forget ingestion on `POST /api/v1/audit/events`, a permission-scoped query API gated by `audit:read`, retention bounded by `AUDIT_RETENTION_DAYS`/`AUDIT_MAX_EVENTS`, and a read-only operator-portal audit view.
- `SPEC-046-audit-reporting-and-export/` extends SPEC-013 by adding two additive endpoints on the existing audit-service — `GET /api/v1/audit/summary` (deterministic aggregates over envelope columns only) and `GET /api/v1/audit/export` (bounded RFC-4180 CSV streamed through platform-gateway) — plus a new `audit-summary.schema.json` contract and a portal Audit view upgrade with Events/Summary tabs and CSV export.
- `SPEC-047-audit-summary-drilldown/` iterates on the SPEC-046 Summary tab: adds an `outcome` filter dimension to all three audit routes, makes every aggregate value clickable into the Events tab with merged filters, replaces the prose total with an antd Statistic row, and wraps bucket tables in collapsible sections.
Dependency direction is strictly forward: SPEC-046 builds on SPEC-013's contract/store/query surface; SPEC-047 builds on SPEC-046's Summary tab. All three preserve the invariant of no new policy actions and no new audit event types beyond what SPEC-013 introduced.
