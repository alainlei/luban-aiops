Every child directory under `docs/specs/` is a self-contained spec following the tri-file contract (`spec.md` + `plan.md` + `tasks.md`) defined in `templates/`, with sequential numbering (`SPEC-001`…`SPEC-066`) and a status header (`draft` → `approved` → `in-progress` → `delivered` → `superseded`). Cross-child relationships are expressed through explicit `extends SPEC-NNN` chains in each spec's summary (e.g. browser tools extend SPEC-049/050/051; approval inbox extends SPEC-020/022/030), so the index in `README.md` is the single source of truth for dependency ordering rather than any runtime wiring. The workspace-level `make verify` command is the enforcement boundary: it runs product tests, renders GitOps overlays, and drives contract tests against `shared/shared-contracts`, binding each delivered spec's acceptance criteria to asserting tests recorded in its `tasks.md`. Tiers separate long-lived architecture records (Tier 1, outside this scope) from short-lived feature specs (Tier 2, this directory) and living state docs (Tier 3, root/product READMEs updated by every delivered spec).
