Three sibling spec directories under `docs/specs/`, each following a uniform three-file layout (`plan.md`, `spec.md`, `tasks.md`) that drives implementation across product boundaries:
- `SPEC-001-release-1-platform-hardening` closes post-Release-0 gaps: gateway auth enforcement (`GATEWAY_REQUIRE_AUTH`), role propagation baseline, session integrity in the transitional runtime, contract validation against `shared/shared-contracts` schemas, backend resolution caching, and CI baselines.
- `SPEC-003-identity-trust-hardening` replaces the caller-asserted identity model with RSA-signed JWTs issued by `identity-broker` and verified locally at the gateway via JWKS (`PyJWT` + `cryptography`), removing per-request introspection and eliminating the `DEFAULT_USER_ID` code fallback.
- `SPEC-009-pre-production-hardening` is the Release 1 closure gate: deterministic credential redaction on tool output before it reaches model providers, plus Kubernetes workload-identity-bound short-lived service tokens replacing the static client secret at the broker exchange (ADR-0004 upgrade path).
Dependency direction inside this module is one-way: specs reference product packages (`products/tool-gateway`, `products/identity-broker`, `products/agent-platform`) and shared contracts but contain no executable code; they are consumed by maintainers to drive PRs and tests. All three specs share a common status lifecycle (`draft` → `approved` → `in-progress` → `delivered`) and a changelog section recording delivery milestones.
