Three independent SPEC directories form a chronological evolution of the session subsystem:
- SPEC-006 introduces a strategy-pattern `SessionStore` protocol with `InMemorySessionStore` / `RedisSessionStore` backends selected via `SESSION_STORE_BACKEND`, adding graceful fallback to memory when Redis is unreachable and Prometheus health reporting.
- SPEC-016 adds a third `PostgresSessionStore` backend behind the same protocol, decoupling platform sessions from AgentScope's kernel Redis by persisting into an in-cluster Postgres `sessions` table with idle-TTL semantics; Redis remains supported but becomes kernel-only.
- SPEC-022 builds on the durable store to expose a v2 session lifecycle API (`GET/DELETE /api/v2/sessions*`) proxied through platform-gateway under new `session:list` / `session:delete` policy actions, defines a schema-extensible `input_modality` field for future voice input, and commits the SPEC-021 dev opt-in as a kustomize profile (`runtime-profiles/mutating-dev`).
Each spec follows the repository's standard tri-file layout (`spec.md` + `plan.md` + `tasks.md`) with Status metadata, Requirements with acceptance criteria, Non-Goals, Risks, and Changelog sections. Dependency direction is strictly forward: SPEC-022 references the stores defined in SPEC-016/006 and the HITL confirmation registry from SPEC-020.
