Three sequential spec artifacts under `docs/specs/`, each a self-contained triple of `plan.md` / `spec.md` / `tasks.md` following the project's SPEC template. They form an additive delivery chain:
- SPEC-049 introduces the `BrowserConnector` in `tool-gateway` (Playwright over CDP to a chromium-headless-shell sidecar), six `web.*` tools, skill frontmatter (`web_target`, `risk_class`), origin allowlist, named credential sets, flow binding, deviation guard, and evidence/audit riding existing contracts.
- SPEC-050 expands the surface by nine tools (`web.select`, `web.extract`, `web.wait_for`, `web.press_key`, `web.hover`, `web.evaluate`, `web.scroll`, `web.upload_file`, `web.switch_frame`) and reorganizes tutorial content into a top-level `samples/` directory with a `skill/` + `demo/` + `README` layout, decoupling tutorials from platform via an optional `skills-samples` ConfigMap mounted at `/skills/samples`.
- SPEC-051 closes the trust-model gap: agent-platform kernel enforces one HITL gate per mutating browser flow via a session-scoped `FlowContext`/`FlowApproval` store, time-bounded by `AGENT_BROWSER_FLOW_APPROVAL_TTL`, and renders flow-semantic confirmation cards (skill title/description/origin/risk_class) instead of bare tool actions; it also reconciles the password-reset sample so the single gate lands on "Confirm reset" rather than sign-in.
Dependency direction is strictly forward: later specs reference earlier ones as lineage but introduce no new policy actions, audit event types, or shared-contract schemas — they ride `tools:invoke` / `tools:mutate`, SPEC-020 confirmation bridging, SPEC-037 signed execution envelopes, and `tool_invoked` events.
