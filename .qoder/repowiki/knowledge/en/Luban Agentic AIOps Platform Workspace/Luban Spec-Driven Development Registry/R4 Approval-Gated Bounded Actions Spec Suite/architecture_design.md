Three sibling spec directories form a phased delivery of the R4 'approval-gated bounded actions' slice:
- SPEC-021 defines the first mutating tool (`k8s.delete_pod`) gated by a new `tools:mutate` policy action, risk-tier admission at the tool-gateway, and the HITL confirmation invariant; it touches `products/tool-gateway`, `products/agent-platform`, `products/platform-gateway`, and `products/operator-portal/web-ui`.
- SPEC-037 builds on SPEC-021 to add HMAC-SHA256-signed execution envelopes (execution-request.schema.json / execution-receipt.schema.json) produced at resume time in agent-service, argument-digest verification at the gateway boundary, durable execution records in Postgres, and receipt visibility on decided confirmation cards — still executing in-process.
- SPEC-038 extracts the in-process call into a standalone `products/execution-runtime` worker that authenticates via a dedicated handoff token, re-verifies the envelope and args digest, performs the tool-gateway call with the forwarded delegated token, writes the signed receipt, and enforces single-flight idempotency keyed by `execution_id`; isolation is enforced at the infrastructure layer (ClusterIP-only, no portal/LGM exposure).
Dependency direction is strictly forward: SPEC-038 inherits the SPEC-037 schemas verbatim and calls `verify_envelope` for the first production use; neither spec changes approval tiers or read-only tool paths. Each spec follows the same plan/spec/tasks triad and tracks status as `delivered` across releases 0.7.0 → 0.19.0 → 0.20.0.
