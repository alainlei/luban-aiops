- Each spec directory carries a fixed plan.md / spec.md / tasks.md triad, with spec.md structured as Summary → Motivation → numbered Requirements (each with acceptance criteria) → Non-Goals → Impact → Open Questions → Changelog.
- Mutating capability is triple-gated across layers: tool-gateway risk-tier admission (`GATEWAY_MUTATING_TOOLS_ENABLED` + `tools:mutate`), agent-platform auto-allow exclusion for non-read tools, and mandatory HITL confirmation — no configuration path auto-runs a mutating tool.
- Fail-closed posture is the default for every security boundary: missing signing key, missing handoff secret, unauthenticated handoff, signature mismatch, and args-digest mismatch all reject before execution and emit a structured audit event rather than degrading.
- New cross-service contracts are additive schema versions under `shared/shared-contracts/schemas/` (e.g. v5→v6 `agent-stream-event.schema.json`, new v1 `execution-request.schema.json` / `execution-receipt.schema.json`) validated by the shared-contracts validator.
- Secrets are provisioned through deploy-chain scripts mirroring the existing `SKIP_*_SECRETS` pattern, surfaced to services as `EXECUTION_*` / `AGENT_EXECUTION_*` settings modules that validate values at startup.
