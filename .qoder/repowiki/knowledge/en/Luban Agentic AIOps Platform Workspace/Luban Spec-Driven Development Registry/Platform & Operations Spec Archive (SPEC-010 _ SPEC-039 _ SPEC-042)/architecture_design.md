Three independent, delivered spec directories under `docs/specs/`, each following the same tri-file layout (`spec.md` + `plan.md` + `tasks.md`) and a uniform header block of `status` / `owner` / `created` / `delivered` / `release slice` / `related ADRs`. Each spec is self-contained: it states Summary → Motivation → numbered Requirements (R-N) with acceptance criteria → Design Decisions (open questions resolved) → Non-Goals → Impact (products touched, contracts touched, identity/policy/audit impact, living-state docs to update) → Open Questions → Changelog. There is no cross-reference code or shared schema in this scope — the files are pure architectural records describing changes across `products/platform-gateway`, `products/tool-gateway`, `products/agent-platform`, `products/operator-portal`, and backend lockfiles.
