This module is a self-contained spec package under `docs/specs/` with three complementary documents that together define one delivery:
- `spec.md` is the authoritative requirements document (status `delivered`, owner workspace maintainers, created/approved/delivered 2026-08-18). It defines five requirements (R-1 through R-5) covering kernel config surfaces (`ReActConfig`, `ContextConfig`, `InjectionConfig`, `ModelConfig`), native structured output replacing SPEC-015's fenced-JSON triage discipline, `AgentStateStore` protocol with `InMemoryAgentStateStore` / `PostgresAgentStateStore` backends, dev-k8s wiring, and observability.
- `plan.md` maps each requirement to affected source files across `products/agent-platform`, `products/incident-service`, `products/platform-gateway`, and `shared/shared-contracts`, and lays out an eight-stage sequencing (settings → store protocol → snapshot/restore → v2 chat schema → incident-service triage → gateway mirror → dev-k8s → metrics/tests/docs).
- `tasks.md` is the living checklist tracking every acceptance criterion against concrete file paths; all tasks are checked off, confirming delivered status.

Dependency direction is outward only: this spec references implementation modules it governs but contains no code. It deliberately excludes adopting agentscope app-layer storage (`create_app`, `RedisStorage`, `AsyncSQLAlchemyStorage`) per ADR-0003, keeping persistence platform-owned via snapshots of `agent.state.model_dump_json()` keyed by session id in an `agent_states` table.
