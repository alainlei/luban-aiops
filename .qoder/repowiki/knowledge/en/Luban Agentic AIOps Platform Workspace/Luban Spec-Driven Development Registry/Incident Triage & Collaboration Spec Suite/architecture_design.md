Three sibling spec directories under `docs/specs/`, each following the standard plan/spec/tasks triple and tracking a single release slice:
- `SPEC-015-incident-triage-and-collaboration/` (R3) defines the canonical incident envelope (`shared/shared-contracts/schemas/incident.schema.json`) and triage report schema, the dual intake service (`products/incident-service` with Alertmanager webhook + manual API), agent-driven triage via platform-gateway's delegated identity chain, read-only tool connectors in tool-gateway, a pluggable `Connector` protocol with a built-in audit sink, and the operator-portal Incidents view.
- `SPEC-043-incident-report-document-type/` (R5) extends the existing SPEC-039 document substrate with an `incident_report` type, adding a bounded incident-service client in agent-platform that assembles a digest from incident envelope, validated triage report, connector dispatch outcomes, and the linked session's two-tier digest; creation is gated by both `documents:create` and `incident:read`.
- `SPEC-045-incident-skill-draft-and-preview/` (R5) builds on SPEC-043's incident client to add `POST /api/v2/incidents/{incident_id}/skill-draft`, reusing the SPEC-044 session-scoped generator with an incident bundle (envelope minus `triage_raw`/session id + validated triage report), a new `incident:skill_draft` policy action, a dedicated `incident_skill_draft_generated` audit event, and a shared preview modal consumed by both the chat header and incident detail entry points.

Dependency direction is strictly forward: later specs depend on contracts and clients introduced by earlier ones (SPEC-045 → SPEC-043 → SPEC-015); no backward references exist. All three are leaf documentation — they declare requirements, acceptance criteria, non-goals, impact matrices, and living-state doc updates but contain no source code.
