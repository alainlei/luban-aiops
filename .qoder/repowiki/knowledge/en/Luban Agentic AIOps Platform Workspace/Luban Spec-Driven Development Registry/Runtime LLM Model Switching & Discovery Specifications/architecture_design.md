Three sequential spec artifacts under `docs/specs/` that form a single feature arc across `products/agent-platform`, `products/platform-gateway`, and `products/operator-portal`:
- SPEC-024 (delivered) introduces a credential-gated catalog, a read-only `GET /api/v2/models` discovery endpoint relayed by platform-gateway, per-session model affinity pinned on the session record, agent rebuild via `RuntimeKernel.ensure_agent`, and enriched audit payloads on `chat_started`/`chat_completed`.
- SPEC-026 (approved) extends the catalog so each provider contributes its full curated model series, moves entry identity from provider name to model name, adds `<PROVIDER>_MODELS` override, consolidates gitops `runtime-profiles/` into a single generic `default/` profile, and aliases legacy provider-name pins.
- SPEC-027 (delivered, 0.10.0) lifts the dynamic-discovery non-goal from SPEC-026: agent-service calls each provider's OpenAI-compatible `/models` behind the same bearer key, applies per-adapter snapshot/modality filters, and serves a fail-soft ladder (live → in-memory last-good → Postgres-persisted `model_discovery_cache` table → curated series) refreshed by a FastAPI lifespan background task with atomic `MODEL_CATALOG` swap.
Dependency direction is strictly forward: SPEC-026 `extends` SPEC-024, SPEC-027 `extends` SPEC-026; contracts touched are additive (`shared/shared-contracts/schemas/model-catalog.schema.json`, chat/session schemas), and no new event types are introduced — only enrichment of existing audit events.
