The repository is a product-oriented monorepo under `products/`, where each directory is an independently buildable, Dockerized service with its own `pyproject.toml`, `.python-version`, `Dockerfile`, `Makefile`, `src/<package>/`, and `tests/`. The runtime surface comprises: `agent-platform` (agent orchestration, sessions, streaming), `platform-gateway` (portal-facing edge with policy enforcement, chat/session proxying, token delegation), `tool-gateway` (normalized tool/connector access including MCP), `identity-broker` (SSO, federation, group normalization), `audit-service` (durable audit ingest/store/query), `incident-service` (Alertmanager intake, triage, collaboration dispatch), `execution-runtime` (isolated bounded workers), `skills-hub` (Git-based skill ingestion/validation/retrieval), and `operator-portal` (Nginx-hosted SPA). Cross-cutting assets live in `shared/`: `shared-contracts` (API/event/policy/domain schemas, SQL, validation scripts), `shared-sdk` (client/auth/tracing helpers), and `shared/platform-ops` (Kubernetes/Kustomize GitOps overlays plus e2e demo scripts). `docs/` holds ADRs, per-SPEC plan/spec/task triplets, release notes, guides, and workspace study spikes. Build orchestration is centralized in the root `Makefile` plus `mk/{defaults,image,python}.mk`; it enumerates `PYTHON_PRODUCTS` and `IMAGE_PRODUCTS`, delegates per-product `sync/test/lint/build/push`, renders Kustomize overlays, validates canonical policies from `shared/shared-contracts/policies/`, enforces version lockstep via `validate-version`, and drives the coordinated `deploy` pipeline against `shared/platform-ops/gitops/dev-k8s`. Dependency direction flows inward: products depend on `shared/shared-contracts` and `shared/shared-sdk` but never on each other's source; inter-service communication goes through the documented API/event contracts.
