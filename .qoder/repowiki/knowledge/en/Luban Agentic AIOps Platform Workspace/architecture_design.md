The repository is a multi-product workspace: `products/` holds each service (agent-platform, execution-runtime, audit-service, identity-broker, incident-service, platform-gateway, skills-hub, tool-gateway, operator-portal), `shared/` centralizes cross-cutting JSON Schema contracts, policy bundles, Kustomize GitOps overlays, dashboards, and e2e scripts, and `docs/` records the spec-driven development lifecycle. Cross-child wiring is enforced at three levels: (1) the root `Makefile` declares `PYTHON_PRODUCTS`, `IMAGE_PRODUCTS`, and `OVERLAYS` to run every product's tests, lint, build, and kustomize render in lockstep; (2) `make sync-policy` copies canonical policy bundles from `shared/shared-contracts/policies/` into both `tool-gateway` and `platform-gateway` plus the dev overlay, keeping policy evaluation consistent across engines; (3) `shared/shared-contracts/scripts/` provides cross-product validators (`validate_policy.py`, `validate_policy_scenarios.py`, `validate_version.py`, `validate_secret_vocabulary.py`, `validate_password_policy.py`) invoked by `make verify`. The coordinated image tag derived from `VERSION` is written to `shared/platform-ops/gitops/dev-k8s/.images.env` so all overlays consume one immutable set of images per build. Samples under `samples/acme-admin/` are deployed out-of-band via `make deploy-samples` so they never enter the base overlay.
