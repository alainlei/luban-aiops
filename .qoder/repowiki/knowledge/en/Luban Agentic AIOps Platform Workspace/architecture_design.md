The workspace is a multi-product monorepo organized by stable architectural boundary:
- `products/` holds each independently deployable service (agent-platform, execution-runtime, identity-broker, audit-service, incident-service, platform-gateway, skills-hub, tool-gateway) plus the operator-portal web UI; every product follows the same layout (`src/<pkg>/api|core|schemas|services`, `Dockerfile`, `Makefile`, `pyproject.toml`, `.python-version`).
- `shared/` contains cross-cutting assets: `shared-contracts/` (Pydantic schemas, SQL, policy definitions, scripts), `platform-ops/` (Kubernetes gitops manifests, dashboards, e2e tests, sample skills), and `base-images/base-uv/Dockerfile`.
- `samples/acme-admin/` is a reference application demonstrating skill authoring, composition, and deployment against the platform.
- `docs/specs/SPEC-NNN-*` directories follow a plan/spec/tasks triad driving feature work; `docs/adr/` records architectural decisions; `docs/guides/` provides operator/user documentation.
- `mk/` provides shared Makefile fragments (`defaults.mk`, `image.mk`, `python.mk`) consumed by each product's `Makefile`.
- Dependency direction is inward: products depend on `shared/shared-contracts` but never on each other directly — inter-service communication goes through the documented contracts and runtime APIs.
- The top-level `Makefile` and `.python-version` anchor workspace-wide tooling (uv-based Python builds); per-product `Makefile`s delegate common tasks to `mk/`.
