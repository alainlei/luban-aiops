The workspace is a multi-product monorepo organized by stable architectural boundary:
- `products/` holds independently deployable services: `agent-platform` (AgenticScope-based agent runtime with kernel, tools, skills, sessions), `platform-gateway` (policy-enforcing HTTP gateway with auth legs and delegation), `execution-runtime` (isolated signed execution worker), `identity-broker` (broker-mediated token exchange), `audit-service`, `incident-service`, `skills-hub`, and `tool-gateway`; each product ships its own `pyproject.toml`, `Dockerfile`, `Makefile`, `src/<pkg>/`, and `tests/`.
- `shared/` provides cross-cutting assets: `shared-contracts` (Pydantic schemas, policy definitions, SQL, scripts consumed as a package), `shared-sdk` (client SDK), and `platform-ops` (GitOps overlays, dashboards, e2e suites, skill bundles).
- `samples/acme-admin` is a reference application demonstrating skill composition, runbooks, and acceptance tests against the platform.
- `docs/specs/SPEC-*` documents feature-driven development artifacts (plan/spec/tasks); `docs/adr/` records architecture decisions; `docs/guides/` and `docs/agentic-aiops-platform/` hold operator/user documentation.
- `mk/` defines shared Makefile fragments (`defaults.mk`, `image.mk`, `python.mk`) reused by every product's `Makefile`.
- Top-level `Makefile` orchestrates workspace-wide tasks; `.python-version` pins the interpreter used across products.
Dependency direction is inward: products depend on `shared/shared-contracts` and `shared/shared-sdk`; samples depend on deployed products; nothing in `shared` depends on any product.
