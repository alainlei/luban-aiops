Two cooperating layers inside the module scope:

- `runtime_kernel.py` defines `AgentKernel`, the single orchestrator that owns an LRU-bounded cache of `agentscope.agent.Agent` instances keyed by `(session_id, read_only)`. It composes toolkit discovery (gateway tools + built-in task tools), middleware stack (`GatewayPermissionMiddleware`, `ToolEvidenceMiddleware`, `TokenUsageMiddleware`, optional tracing/reply-budget), state snapshot/restore via `AGENT_STATE_STORE`, evidence persistence via `EVIDENCE_STORE`, HITL mutation gating, execution admission via `ExecutionRecovery`, and streaming prose redaction via `StreamingProseRedactor`. The kernel never talks to an LLM directly — it delegates model construction to a provider adapter obtained from `get_provider(settings.provider)`.
- `providers/` is a small adapter layer. `base.py` declares the abstract `AgentScopeProvider` interface (`build_model`, `validate`, `resolved_model_name`, `resolved_base_url`, `describe`, plus live-discovery filters). Concrete implementations live in sibling modules (`dashscope.py`, `deepseek.py`, `luban.py`, `openai.py`). `registry.py` holds a static `_PROVIDERS` dict keyed by provider name and exposes `get_provider()` / `supported_provider_names()`, which `__init__.py` re-exports as the package surface.

Dependency direction is one-way: `runtime_kernel.py` depends on `providers.get_provider`; providers depend only on `base.py` and their vendor SDKs. Cross-cutting concerns (state, evidence, audit, flow approvals, secret redaction, model catalog, metrics) are imported from sibling `agent_service.services.*` packages rather than implemented here.
