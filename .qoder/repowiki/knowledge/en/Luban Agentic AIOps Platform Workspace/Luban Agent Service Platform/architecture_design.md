The `agent_service` package is a single Python application whose children are layered around two entrypoints (`main.py` for the HTTP API, `native_service.py`/`agent_app.py` for the worker/runtime process) that share one dependency graph declared in `pyproject.toml`. Cross-child wiring follows a consistent pattern:
- `shared_infrastructure` (config/env, Prometheus + OpenTelemetry, FastAPI/uvicorn bootstrap, gateway tool wrappers) is imported by every other child to obtain settings, metrics, tracing, and the `GatewayTools` client.
- `api_layer` (FastAPI v2 routers + Pydantic schemas) is the only inbound boundary; it delegates to services in `session_management`, `execution_orchestration`, `hitl_and_flow_approvals`, `documents_and_evidence`, and `skill_authoring_and_graduation` rather than implementing business logic itself.
- `runtime_kernel_and_providers` is the central runtime: all mutating flows (execution invocation, HITL confirmations, skill graduation) ultimately call into the AgentScope kernel through provider adapters (`openai`, `dashscope`, `deepseek`, `luban`) registered via `providers.registry`.
- Persistence is split by concern but uniformly accessed through per-service clients: Postgres-backed `execution_records`/`execution_recovery`/`confirmation_records`/`operation_documents`/`evidence_store` and Redis-backed `session_store`; tests swap these with in-memory or `fakeredis` fakes.
- JSON Schema files under `contracts/` define the durable wire format between the agent service and the external execution-runtime worker, consumed by both the invocation coordinator and the recovery projections.
