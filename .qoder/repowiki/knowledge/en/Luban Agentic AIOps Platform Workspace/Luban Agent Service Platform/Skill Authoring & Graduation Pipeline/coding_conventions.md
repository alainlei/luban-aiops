- Draft outputs are assembled as Markdown with a YAML frontmatter fence followed by a body containing an HTML-comment provenance block (`<!-- ... -->`) carrying session/incident id, UTC date, platform version, and mode tag.
- Secret exposure is guarded by a shared `REDACTION_VALUE_PATTERNS` tuple (private-key blocks, JWTs, Bearer/Basic headers, AWS access keys) applied both during post-processing of generated prose and as a pre-render refusal check on graduated traces.
- All string fields emitted into skill documents are clamped to explicit Skill Format v1 caps (`MAX_TITLE_CHARS`, `MAX_DESCRIPTION_CHARS`, `MAX_TAG_CHARS`, `MAX_TAGS`, `MAX_VERSION_CHARS`, `MAX_BODY_BYTES`) regardless of model obedience.
- Failure paths degrade to a deterministic skeleton rather than raising: LLM parse/model errors return `None` so callers fall back to `build_skeleton`/`build_incident_skeleton`, and store failures degrade graduation candidacy without breaking the chat stream.
- Cross-component security constants (secret patterns, body caps, step budgets) are duplicated as module-level constants with comments citing their authoritative source file, because products do not import each other — drift is documented rather than eliminated by cross-import.
- Timestamps are normalized through `_canonical_timestamp` / `_iso` helpers to second-precision UTC ISO strings so the in-memory and Postgres backends present identical ordering semantics for declaration-vs-capture comparisons.
