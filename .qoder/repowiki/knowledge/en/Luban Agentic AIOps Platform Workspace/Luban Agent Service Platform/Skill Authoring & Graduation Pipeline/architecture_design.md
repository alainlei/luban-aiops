Three cooperating services form a two-stage pipeline over SPEC-044/045 (knowledge draft) and SPEC-055 (executable flow graduation):

- `skill_draft.py` is the LLM-assisted knowledge-draft producer. It builds a digest-only bundle (session + optional incident triage, never raw transcripts or evidence payloads), calls the runtime kernel's model with a bounded timeout (`SKILL_DRAFT_TIMEOUT_SECONDS`), parses a fenced `skill-frontmatter` JSON contract via Pydantic, applies deterministic guardrails (redaction vocabulary shared with tool-gateway, Skill Format v1 caps, UTF-8 body truncation), and falls back to a format-valid facts-only skeleton on any parse or generation failure — so the path never raises a 500.
- `authoring_trace.py` provides durable, replay-oriented capture of approved mutating steps per chat session, independent of the ephemeral execution records. It exposes an `AuthoringTraceStore` Protocol with two implementations: `InMemoryAuthoringTraceStore` (dev/CI) and `PostgresAuthoringTraceStore` (deployed, using the same SPEC-016 sessions DB). The Postgres backend owns DDL (`authoring_trace`, `authoring_trace_target`), in-place migration (`flow_origin` column), advisory locks per session to serialize append vs close, and lifecycle-bound idle GC (`AGENT_AUTHORING_TRACE_IDLE_DAYS`). Each step carries references (`execution_id`, `confirm_id`) rather than duplicating signed receipts; `flow_origin` is recorded post-hoc from the receipt seam to corroborate that mutations landed on the declared target origin.
- `skill_graduation.py` is the deterministic renderer. `revalidate_blast_radius` re-applies the gateway's replay guards at graduation time (step budget, origin allowlist against declared `web_target`, write-class consistency, credential-set resolution, secret-literal shape detection) and returns a `BlastRadius` report; only if it passes does `build_executable_flow_draft` render the trace into a YAML-frontmattered Markdown runbook. No model call is involved — the draft is deterministic over its inputs plus the UTC date in the provenance block.

Dependency direction is one-way: `skill_graduation` imports shared constants (`MAX_BODY_BYTES`, `REDACTION_VALUE_PATTERNS`, `postprocess`, `provenance_block`, `slug_from_title`) from `skill_draft`, while `authoring_trace` has no dependency on either. Both draft producers converge on the same redaction vocabulary and frontmatter contract so skills-hub ingestion sees one notion of safety.
