Three sibling sub-packages form the shared foundation layer consumed by higher-level services:

- `core/` — infrastructure primitives. `config.py` caches a single `RuntimeSettings` instance via `lru_cache(maxsize=1)`; `env.py` provides typed `get_env_value` / `get_env_int` helpers that fall back across multiple env var names. `observability.py` configures Python's root logger to INFO (overridable via `LOG_LEVEL`) and exposes `log_event` for structured JSON audit records. `telemetry.py` implements an opt-in OTLP push pipeline gated by `OTEL_ENABLED`, lazily initializing TracerProvider/MeterProvider/LoggerProvider and attaching FastAPI + HTTPX instrumentation; it also exposes `current_trace_id()` used for correlation. `metrics.py` defines all prometheus_client counters/histograms/gauges at module level (so repeated `create_app()` in tests never double-register) and installs a RED middleware on `/metrics`; every metric is mirrored through `MetricsMirror` into the OTel meter with the same name and bounded label set, keeping both surfaces in sync. `request_context.py` resolves the inbound `x-request-id` by preferring the portal-supplied value, then the active OTel trace id, then a generated UUID.
- `entrypoints/` — process launchers. `native.py` builds an AgentScope app backed by Redis storage/message bus and a local workspace manager, driven by a frozen `NativeServiceSettings` dataclass read from `AGENTSCOPE_*` / `AGENT_NATIVE_*` env vars, and runs it under uvicorn. `runtime.py` builds an `AgentApp` from `agentscope_runtime.engine.app`, wiring a streaming query handler that translates `TEXT_BLOCK_DELTA` / `THINKING_BLOCK_DELTA` events into `Msg` objects and persists session state around each reply.
- `tools/` — gateway client for AgentScope Toolkits. `gateway_tools.py` discovers tools via GET `/api/v2/tools` and invokes them over POST `/api/v2/tools/invoke` using `httpx.AsyncClient`. It carries per-call identity through `ContextVar`s (`DELEGATED_TOKEN`, `CHAT_SESSION_ID`, execution envelope vars), normalizes gateway schemas into AgentScope-compatible shapes, and routes mutating tools either through a legacy handoff worker or a v3 durable coordinator depending on whether a run guard is bound. Errors are surfaced as structured `ToolChunk` payloads rather than exceptions so evidence middleware can still emit frames.

Dependency direction is one-way: `entrypoints` and `tools` depend on `core`; `core` has no intra-module dependencies beyond stdlib and third-party libs.
