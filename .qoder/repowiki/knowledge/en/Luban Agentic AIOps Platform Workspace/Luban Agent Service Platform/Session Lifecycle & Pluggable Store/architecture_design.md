Three-layer split inside the module:
- `session_service.py` is the stateless API surface: it owns business rules (owner checks via `_assert_session_owner`, title minting from the first user turn with `redact_user_text`, list cap of 50, fail-open bookkeeping for `touch_session`/`pin_session_model`) and coordinates cleanup of sibling stores (`AGENT_STATE_STORE`, `EVIDENCE_STORE`, `CONFIRMATION_RECORD_STORE`, `EXECUTION_RECORD_STORE`, `FLOW_APPROVALS`, `FLOW_CONTEXTS`, `AUTHORING_TRACE_STORE`) on `delete_session`.
- `session_store.py` defines a `runtime_checkable SessionStore` Protocol exposing create/get/list/delete/touch/title/model/version methods, then implements three backends — `InMemorySessionStore` (TTL + max-entry eviction), `RedisSessionStore` (JSON blobs under `session:` keys, NX-minted titles under `session:title:`, sorted set `user_sessions:{user_id}` scored by `created_at`), and `PostgresSessionStore` (DDL in `_SESSIONS_DDL`, idle-TTL refresh via `last_accessed_at`, server-side capped ordered list). A `build_session_store()` factory reads `SESSION_STORE_BACKEND` / `SESSION_TTL_SECONDS` / Redis / Postgres env vars and falls back to memory when Redis or Postgres are unreachable, emitting metrics via `record_session_store_backend` / `record_session_store_fallback` / `record_session_store_error`. The module exposes a singleton `SESSION_STORE` consumed by the service layer.
- `session_transcript.py` is an independent best-effort reader that pulls the agent's JSON snapshot from `AGENT_STATE_STORE`, flattens `AgentState.context` into `{role, content}` turns (skipping system/tool frames), and applies credential masking through `prose_redaction.redact_transcript` before returning `(transcript_available, turns)`.

Dependency direction is one-way: service → store protocol; transcript → agent_state_store + prose_redaction. No cross-imports between the three files except the service importing the store singleton.
