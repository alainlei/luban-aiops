Layered FastAPI application with clear internal boundaries:
- `app.py` + `main.py` assemble the FastAPI lifespan (DB store init, sync manager start/stop), HTTP middleware for request-id correlation, metrics/telemetry wiring, and expose the uvicorn entrypoint.
- `api/router.py` is the single router assembly point; route modules under `api/routes/` (`health`, `skills`, `status`) are thin HTTP adapters over services.
- `services/` holds domain logic: `skill_store.py` defines a `SkillStore` Protocol with two backends (`InMemorySkillStore` for dev/tests, `PostgresSkillStore` using psycopg v3) selected by `SKILLS_STORE_BACKEND`; `sync.py` runs per-source periodic syncs (local directory walk or git clone/fetch/reset); `ingestion.py` parses YAML frontmatter and enforces size/slug constraints; `scoring.py` provides the shared IDF-weighted scorer used identically by both backends; `query_auth.py` handles Basic/workload-token auth; `audit_emitter.py` fire-and-forgets usage events.
- `core/` is framework-agnostic infrastructure: frozen-dataclass settings (`config.py`), Prometheus metrics, OpenTelemetry logging/tracing, async request-context propagation, and runtime bootstrap helpers.
- `schemas/skill.py` declares the Pydantic `Skill` model consumed by all layers.
- Dependency direction is strictly inward: routes → services → core/schemas; no cross-imports between sibling service modules except through the `SkillStore` protocol. The PostgreSQL backend owns raw SQL DDL/indexes in `_DDL` and shares the exact `_SEARCH_TSVECTOR` expression between GIN index and query prefilter to prevent drift.
