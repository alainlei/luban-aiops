Two-layer design inside `platform_gateway.services` plus a data package:
- `policy_engine.py` is the core: it defines frozen dataclasses (`PolicyRule`, `ApprovalSpec`, `PolicyDecision`) and a module-level singleton cache (`_bundle`, `_bundle_version`, `_configured_path`, `_bundle_hash`). `load_bundle()` resolves either an on-disk path from `PlatformGatewaySettings.policy_path` or the packaged default via `importlib.resources`, parses YAML with `yaml.safe_load`, validates every field in `_parse_rules` / `_parse_approval`, and caches the result keyed by configured path. `evaluate()` implements precedence deny > require_approval > allow with highest-priority-wins within each outcome class; disabled rules are skipped. A `PROTECTED_ACTIONS` frozenset enumerates every gateway route action so routes not listed here are platform plumbing exempt from enforcement.
- `policy_matrix.py` is a read-only transparency layer: it reuses `evaluate()` to compute a boolean matrix per visible role (admin sees all roles, others see only their own) plus an additive `approval_requirements` structure for `require_approval` cells, exposing version/source/sha256 metadata.
- `policies/policy-default.yaml` is the bundled default bundle loaded when no `PLATFORM_GATEWAY_POLICY_PATH` is set; `policies/__init__.py` marks the package for resource discovery.

Dependency direction is one-way: `policy_matrix` imports from `policy_engine`; both depend only on `core.config.PlatformGatewaySettings` and shared schemas — no HTTP, no DB, no external services. The module is designed as a future POST `/policy/evaluate` endpoint replacement (see docstring).
