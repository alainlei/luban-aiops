The module is organized as a flat set of domain-scoped route modules under `api/routes/` (auth, identity, sessions, chat, audit, incidents, policy, tools, skills, documents, models, approvals, health, runtime), each defining its own FastAPI `APIRouter`. The single entry point `api/router.py` instantiates a top-level `APIRouter` and `include_router`s every sub-router, which is what the gateway application mounts at `/api/v1`. Cross-cutting behavior — identity normalization, policy authorization, auditing, and observability — is applied inside each route handler rather than via middleware, so the router itself only wires routes together. Upstream calls are delegated to shared service clients (`services.agent_client`, `services.incident_client`) rather than being implemented inline in the handlers.
