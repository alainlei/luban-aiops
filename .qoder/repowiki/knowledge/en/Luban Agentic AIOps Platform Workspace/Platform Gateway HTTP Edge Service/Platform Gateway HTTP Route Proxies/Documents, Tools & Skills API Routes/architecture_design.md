Three sibling FastAPI `APIRouter` modules (`documents.py`, `tools.py`, `skills.py`) each register a `/api/v1/...` sub-path and follow an identical edge-gateway pattern: every handler resolves a request id via `resolve_request_id`, resolves caller identity through `resolve_request_identity`, enforces a policy action from `platform_gateway.services.policy_engine` (e.g. `ACTION_DOCUMENTS_CREATE`, `ACTION_TOOLS_LIST`, `ACTION_SKILLS_READ`), then delegates to a service-layer client in `platform_gateway.services`. Documents are owned by the gateway itself (CRUD + publish/delete against `gateway_service`). Tools and skills are read-only proxies: tools discovery obtains a broker-mediated delegated token (audience `tool-gateway`) via `obtain_delegated_token` and forwards it to `tool_gateway_client`; skills listing uses the gateway's own Basic credential against `skills_hub_client` so the user token is never forwarded. Each route emits a structured event via `core.observability.log_event` keyed on the operation name. The module depends only outward on `core.*` (config, observability, request context) and `services.*` — no cross-imports between the three route files.
