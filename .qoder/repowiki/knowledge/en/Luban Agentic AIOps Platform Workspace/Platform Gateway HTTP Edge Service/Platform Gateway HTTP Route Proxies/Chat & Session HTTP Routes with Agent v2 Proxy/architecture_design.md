Two FastAPI `APIRouter` modules (`chat.py`, `sessions.py`) expose `/api/v1/chat*` and `/api/v1/sessions*` endpoints. Each handler follows a fixed pipeline: resolve request id, resolve identity via `gateway_service.resolve_request_identity`, enforce authorization through `policy_engine` action constants (e.g. `ACTION_SESSION_CREATE`, `ACTION_CHAT_CONFIRM`), obtain a delegated token via `delegation_client.obtain_delegated_token`, call business logic in `gateway_service` (which wraps `agent_client`), then emit structured logs via `core.observability.log_event` and an audit event via `audit_emitter`. The actual HTTP calls to the downstream agent-service live in `services/agent_client.py`, which is a thin httpx-based client over `settings.agent_service_url/api/v2/*`; it constructs per-call headers (`x-request-id`, `X-User-ID`, optional `Authorization` bearer) via `_headers` and uses short-lived `httpx.AsyncClient` instances scoped to each function. Streaming endpoints (`open_chat_stream`, `open_chat_confirm_stream`) return `AsyncIterator[str]` SSE lines after eagerly checking upstream status codes so 4xx/5xx are surfaced as HTTP errors rather than empty streams. Dependency direction is one-way: routes → gateway_service → agent_client → httpx → agent-service; routes never import agent_client directly.
