- Every route handler resolves `request_id` via `resolve_request_id(x_request_id)`, obtains identity through `resolve_request_identity`, enforces a policy action constant from `platform_gateway.services.policy_engine`, then delegates to `gateway_service` — this three-step prelude is repeated across all endpoints.
- Structured observability is emitted on every successful path using both `log_event` (for metrics/tracing) and `build_audit_event` + `emit_audit_event` (for durable audit ledger), with fields like `authenticated=identity.subject != "dev"` and `roles=identity.roles` included consistently.
- Downstream agent calls use `async with httpx.AsyncClient(timeout=...)` blocks that call `response.raise_for_status()` and return `response.json()`, keeping error propagation uniform across sync-style functions.
- SSE streaming functions build the request with `client.send(request, stream=True)`, eagerly check `response.status_code >= 400` before yielding any line, and wrap the iterator in a try/finally that closes both response and client.
- Optional payload/query parameters are filtered out when None (e.g. dict comprehensions or conditional inclusion) so omitted values produce byte-identical historical requests to the agent-service.
- Route docstrings cite the governing spec requirement (e.g. `SPEC-022 R-1`, `SPEC-056 R-6 / OQ-1`) explaining why a gate lives at the policy boundary rather than delegating ownership checks downstream.
