The module is split into three cooperating layers:
- `app.py` is the single entry point: `create_app()` builds the FastAPI instance, registers a request-logging middleware (resolving `x-request-id`, timing, and emitting a structured `http_request` event), includes the API router, then wires up metrics and telemetry.
- `core/config.py` and `core/runtime.py` define frozen dataclass settings (`PlatformGatewaySettings`, `GatewayRunSettings`) loaded from environment variables via `from_env()`, cached through `@lru_cache(maxsize=1)` on `get_settings()`; defaults cover agent-service, identity-service, audit/incident/tool-gateway/skills-hub backends plus JWKS/issuer/audience policy knobs.
- `core/observability.py` raises the root logger to INFO so structured JSON events survive Uvicorn's default WARNING level and exposes `log_event` for uniform audit-trail records.
- `core/metrics.py` implements an always-on RED surface with `prometheus_client`: a FastAPI HTTP middleware recording `http_requests_total` / `http_request_duration_seconds`, a `/metrics` endpoint, and typed counters/histograms for policy decisions, token verification, delegation exchange/cache, and audit emits. Every metric is paired with a call to `MetricsMirror` so it is also pushed over OTLP when enabled.
- `core/telemetry.py` provides opt-in OpenTelemetry tracing/metrics/logs push via OTLP HTTP/protobuf, gated by `OTEL_ENABLED`; it lazily installs `TracerProvider`, `MeterProvider`, `LoggerProvider`, FastAPI and HTTPX instrumentors, and bridges Python `logging` into OTLP logs. `MetricsMirror` re-emits the prometheus families as OTel instruments (lazy, fail-open, no-op when disabled) so both scraping and push paths carry identical domain metrics.
- `core/request_context.py` resolves correlation keys: `resolve_request_id` prefers inbound `x-request-id`, falls back to the active OTel trace id, else generates a UUID; `resolve_user_id` applies a fixed precedence chain (authenticated > explicit > header > default).
- `schemas/api.py` holds Pydantic v2 models mirroring shared-contracts schemas (chat, session, document, incident, identity-context, policy-matrix) with `ConfigDict(extra="forbid")` and spec-linked comments referencing SPEC-NNN requirements.

Dependency direction inside the module: `app.py` depends on all core modules; `metrics.py` depends on `telemetry.MetricsMirror`; `request_context.py` depends on `telemetry.current_trace_id`; `config.py` and `runtime.py` are leaf dependencies only consumed by higher layers. The `schemas` package has no intra-module dependency on `core`.
