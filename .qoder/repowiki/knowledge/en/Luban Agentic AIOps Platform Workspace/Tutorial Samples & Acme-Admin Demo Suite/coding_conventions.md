- Each sample directory follows the fixed shape `README.md` + optional `WALKTHROUGH.md` + `skill/` + `demo/demo.sh`, with `skill-graduation` being the documented exception where the demo produces the skill instead of shipping one.
- Demo scripts are executable shell scripts sourced from `demo-lib.sh` rather than executed independently, keeping prerequisites and environment overrides (`NAMESPACE`, `IDENTITY_URL`, `GATEWAY_URL`, `TEST_USER`, `APPROVER_USER`, `CROSS_TARGET`, `RUN_CHAT_LEG`) centralized.
- Skill document filenames are chosen deliberately to avoid ConfigMap key collisions — e.g. `ResetAcmePassword.md` rather than `ResetUserPassword.md` — because `deploy-samples.sh` derives skill ids from the mounted file name with lowercasing and slash-to-dash flattening.
- The five-rung ladder is ordered by increasing card count (0 → 0 → 1 → 1 → 2) and each rung's README/WALKTHROUGH explicitly states which portal surface (Chat vs Studio) and which approval model (`action` vs `flow`) it demonstrates.
- Deployment and assertion are combined: `deploy.sh` does not exit 0 unless health, auth, seed data, image freshness, and NetworkPolicy reachability all pass, with CNI-dependent checks downgraded to warnings.
