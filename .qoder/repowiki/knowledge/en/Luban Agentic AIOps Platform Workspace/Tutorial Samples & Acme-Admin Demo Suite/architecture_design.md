Two-layer layout: a top-level `samples/` registry plus the `acme-admin/` category which is both a sample and the shared target for all of them.

- Top level: `deploy-samples.sh` is the only cluster-coupling script; it discovers any directory under `samples/` that contains a `skill/` subdirectory, packs every `skill/*.md` into the `skills-samples` ConfigMap (key `<leaf>-<flat-path>`), applies it to the `dev-luban-aiops` namespace, and restarts `skills-hub` so the `samples` source re-ingests. Skill ids become `samples/<slug>` derived from the mounted file name.
- `acme-admin/` is a suite, not a single sample: it owns the FastAPI application (`app/` with its own Dockerfile, pyproject.toml, tests, Makefile), Kustomize deploy manifests (`deploy/`), shared demo plumbing (`demo-lib.sh`, `demo-suite.sh`), and the seven per-sample directories (`health-check`, `user-status`, `lock-unlock-user`, `password-reset`, `composition`, `adhoc-password-reset`, `skill-graduation`).
- Each sample follows the invariant layout `README.md` + optional `WALKTHROUGH.md` + `skill/` + `demo/demo.sh`; `skill-graduation` intentionally ships no `skill/` because the demo produces the skill artifact.
- Dependency direction is strictly tutorial → platform: the base overlay names nothing here, and samples are installed out-of-band after `make deploy`. The `acme-admin` app itself is built as a container image and deployed via `make deploy-sample-app` / `deploy.sh`, which asserts health, auth, seed data, and NetworkPolicy reachability before declaring success.
