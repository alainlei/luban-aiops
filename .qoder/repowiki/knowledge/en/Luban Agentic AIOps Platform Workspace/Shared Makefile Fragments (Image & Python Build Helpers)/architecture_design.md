Three sibling `.mk` files consumed by product `Makefile`s via `include ../../mk/...`:
- `defaults.mk` is the single source of truth for overridable variables (`IMAGE_PLATFORM`, `IMAGE_TAG_PREFIX`, `REGISTRY`, `BASE_UV_*`, etc.), guarded against double inclusion with the `LUBAN_DEFAULTS_INCLUDED` flag; every value uses `?=` so command-line overrides win.
- `image.mk` depends on `defaults.mk` (included relative to itself so standalone `make -C products/<name>` resolves the same config) and exposes `.PHONY: help build push lint`; it computes `IMAGE_REF` from `IMAGE_NAME`/`IMAGE_TAG`/`REGISTRY`, builds with `docker build --platform $(IMAGE_PLATFORM)`, optionally re-tags into `$(REGISTRY)/luban-aiops/$(IMAGE_NAME):$(IMAGE_TAG)`, and lints Dockerfiles via hadolint (with a docker-run fallback).
- `python.mk` provides `.PHONY: sync test` running `uv sync --frozen` and `uv run pytest` with OTel exporters disabled so tracing tests stay quiet without disabling the SDK.
Dependency direction is one-way: product Makefiles include these fragments; fragments do not include each other except `image.mk -> defaults.mk`. The root Makefile also includes `defaults.mk` directly, keeping root-driven and per-product invocations in sync.
