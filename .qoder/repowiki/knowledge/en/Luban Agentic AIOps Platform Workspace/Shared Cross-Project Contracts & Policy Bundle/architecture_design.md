This module is a pure contract layer with no runtime code — it ships schemas, policy data, SQL, and validation helpers consumed by `products/` services and `shared/shared-sdk`. Internal layout:
- `schemas/`: 33 JSON Schema files (draft-2020-12) grouped by domain: portal/gateway chat v1, platform-owned agent-service v2 (`agent-*`), identity/JWT claims, policy models (`policy-rule`, `policy-decision`, `policy-matrix`), tool execution envelopes, execution-runtime payloads (SPEC-038/063), audit/incidents/skills/model-catalog/operations documents. Each schema uses `$id` under `https://metasync.github.io/luban-aiops/schemas/...` and `additionalProperties: false` for strictness.
- `policies/`: `policy-default.yaml` is the single canonical action-authorization bundle (v1, `action_authz` domain); `policy-scenarios.yaml` records expected outcomes per (role, action) pair; `password-policy.yaml` holds password rules. The bundle's semantics (deny-by-default, precedence deny > require_approval > allow, tier_1/tier_2 approval) are enforced by gateways at runtime.
- `scripts/`: Python validators keyed on `jsonschema.Draft202012Validator` and PyYAML — `validate_policy.py` checks rule schema + duplicate IDs, `validate_password_policy.py`, `validate_policy_scenarios.py`, `validate_secret_vocabulary.py`, `sync_execution_contracts.py`, `policy_diff.py`, `validate_version.py`. These are invoked via Make targets (`make verify`, `make sync-policy`, `make policy-diff`).
- `sql/execution-ledger-v1.sql`: DDL for the durable execution ledger consumed by the execution runtime.
- Top-level docs: `README.md` documents ownership, scope, header conventions (`X-User-ID`, `x-request-id`), identity-token JWT flow (RSA-256 + JWKS), policy evaluation semantics, tool execution naming, and observability conventions; `observability-conventions.md` and `skill-format.md` are reference docs.

Dependency direction is one-way: consumers import these schemas/policies; this module imports nothing from the rest of the repo. Versioning is manual — bump the `version` field in bundles and rely on Git history as authority, with gateway SHA-256 fingerprints for deploy-time confirmation.
