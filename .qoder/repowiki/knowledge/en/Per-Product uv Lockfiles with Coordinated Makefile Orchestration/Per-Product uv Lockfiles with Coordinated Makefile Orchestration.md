# Dependency Management in the Luban Agentic AIOps Platform

## Approach

The repository is a multi-product workspace (8 Python FastAPI services + 1 React SPA) that manages dependencies through **per-package `pyproject.toml` files paired with per-package `uv.lock` lockfiles**, orchestrated by a root GNU Makefile. There is no monorepo dependency manager (no `pyproject.toml` at the repo root, no `pnpm-workspace.yaml`, no `go.mod`). Each product under `products/<name>/` is an independent Python package.

The shared build fragments live in `mk/`: `mk/python.mk` provides the canonical `sync` and `test` targets that every Python product includes, and `mk/defaults.mk` pins the base image's `UV_VERSION=0.12.1` and `PYTHON_VERSION=3.12`. The root `Makefile` declares the Python products list (`PYTHON_PRODUCTS := agent-platform audit-service execution-runtime identity-broker incident-service platform-gateway skills-hub tool-gateway`) and dispatches `make sync` / `make test` across all of them.

## Key Files

- `mk/python.mk` — canonical `uv sync --frozen` target used by every Python product; also sets `OTEL_TRACES_EXPORTER=none OTEL_METRICS_EXPORTER=none OTEL_LOGS_EXPORTER=none` around `uv run pytest` so tests stay free of OTLP retry noise while keeping the SDK active for tracing tests.
- `mk/defaults.mk` — single source of truth for overridable build settings including `BASE_UV_UV_VERSION=0.12.1` and `BASE_UV_PYTHON_VERSION=3.12`; values use `?=` so command-line overrides always win.
- Root `Makefile` — aggregates per-product routines, defines `PYTHON_PRODUCTS`, and runs coordinated `sync`, `test`, `build`, `push`, `verify` targets across all products.
- Per-product `products/*/pyproject.toml` — declares runtime dependencies, `requires-python = ">=3.11"`, `[dependency-groups].dev` (pytest, jsonschema), and `[build-system] requires = ["uv_build>=0.8.14,<0.9.0"]` with `build-backend = "uv_build"`.
- Per-product `products/*/uv.lock` — frozen lockfile generated by `uv` (committed to the repo).
- `products/operator-portal/web-ui/app/package.json` — the only Node.js manifest; uses caret ranges (`^6.6.2`, `^19.2.8`) with `engines.node = ">=22.22.2"`; `node_modules/` is gitignored.
- `.gitignore` — ignores `node_modules/`, `.venv/`, `venv/`, `__pycache__/`, `.pytest_cache/`, `.mypy_cache/`, `.coverage`, `dist/`, `build/`, `.turbo/`, `.next/`.
- `shared/base-images/base-uv/Dockerfile` — builds the reproducible base image whose `UV_VERSION` and `PYTHON_VERSION` are pinned via `mk/defaults.mk`.

## Architecture and Conventions

### Python packages

Every Python product follows the same shape:

```
[project]
name = "..."
version = "0.44.0"          # synchronized with root VERSION
requires-python = ">=3.11"
dependencies = [
  "fastapi>=0.115,<1.0",
  "pydantic>=2.8,<3.0",
  "opentelemetry-sdk>=1.25,<2.0",
  ...
]
[dependency-groups]
dev = ["pytest>=8.3,<9.0", "jsonschema>=4.23,<5.0"]
[build-system]
requires = ["uv_build>=0.8.14,<0.9.0"]
build-backend = "uv_build"
```

Dependency versioning uses **broad lower bounds with tight upper bounds** (e.g. `fastapi>=0.115,<1.0`, `pydantic>=2.8,<3.0`, `opentelemetry-sdk>=1.25,<2.0`, `prometheus-client>=0.20,<1.0`, `PyJWT>=2.8,<3.0`, `PyYAML>=6.0,<7.0`, `redis>=5.0/<6.2,<7.0`, `cryptography>=43.0,<51.0`). This allows minor/patch upgrades within a major line but blocks breaking changes. Some dependencies use open-ended upper bounds (e.g. `agentscope>=2.0.4,<3.0`, `apscheduler>=3.11,<4.0`, `httpx>=0.27,<1.0`, `playwright>=1.48,<2.0`, `kubernetes>=30.0,<33.0`, `elasticsearch>=8.0,<9.0`).

All eight Python services share a common dependency surface: FastAPI, Pydantic, Uvicorn, OpenTelemetry SDK + HTTP exporter + FastAPI/HTTPX/logging instrumentation, Prometheus client, PyJWT or PyYAML where needed, and psycopg[binary] where Postgres is used.

### Lockfiles and reproducibility

- `uv sync --frozen` is the only supported install path (via `mk/python.mk`); it refuses to resolve against the network if the lockfile is out of date, forcing developers to regenerate `uv.lock` explicitly.
- `uv.lock` files are committed alongside each `pyproject.toml`.
- The shared base image `luban-aiops/base-uv:<tag>` is built from `shared/base-images/base-uv/Dockerfile` with `--build-arg UV_VERSION=$(BASE_UV_UV_VERSION)` and `--build-arg PYTHON_VERSION=$(BASE_UV_PYTHON_VERSION)`, pinning the resolver environment.
- Container images are tagged with a coordinated `<semver>-<prefix>[-<profile>]-<gitsha>` scheme computed from the root `VERSION` file plus git state; `make build` writes `shared/platform-ops/gitops/dev-k8s/.images.env` with the exact image digests consumed by GitOps overlays.

### Node.js frontend

The operator portal SPA (`products/operator-portal/web-ui/app/package.json`) is the only JavaScript code. It uses Vite + Vitest + TypeScript + Ant Design. Dependencies use caret ranges (`^`), which is the standard npm convention for allowing compatible updates. `node_modules/` is gitignored and not part of the Docker build (the Dockerfile installs dependencies during image build). There is no `package-lock.json` visible in the tree; the `web-ui/node_modules/` directory exists as a local artifact.

### Cross-cutting orchestration

The root `Makefile` is the single entry point:

- `make sync` — iterates `$(PYTHON_PRODUCTS)` and runs `make -C products/$p sync` (which invokes `uv sync --frozen`).
- `make test` — same iteration running pytest under the env vars set by `mk/python.mk`.
- `make verify` — the pre-commit/pre-push gate that runs `test overlays validate-dashboards validate-policy validate-policy-scenarios validate-version validate-secret-vocabulary validate-password-policy secret-delivery-demo portal-test execution-failure-test`.
- `make build` / `make push` — build/push all container images with the coordinated tag.
- `make base-images` — rebuilds `shared/base-images/base-uv` with the pinned `UV_VERSION` and `PYTHON_VERSION`.

### Version synchronization

The `VERSION` file at the repo root is the single source of truth for the platform release semver. The root `Makefile` computes `PLATFORM_VERSION := $(shell cat VERSION 2>/dev/null)` and enforces that every product's `pyproject.toml` version and every service's `metadata.py` `SERVICE_VERSION` match it via `make validate-version` (implemented by `shared/shared-contracts/scripts/validate_version.py`). Release notes repeatedly document this choreography: updating `VERSION` triggers synchronized bumps across `VERSION`, eight `pyproject.toml` files, eight `metadata.py` files, two `__init__.py` files, and eight `uv.lock` re-locks.

### Private registries and vendoring

No private registry configuration (e.g. `uv.config.toml`, `pip.conf`, `~/.npmrc`) was found in the repository. No vendored third-party source trees exist outside `products/operator-portal/web-ui/node_modules/` (which is gitignored). All Python dependencies are resolved from the public PyPI index via `uv`. The `agentscope` and `agentscope-runtime` dependencies indicate reliance on external libraries rather than vendored copies.

## Conventions and Constraints

- **Each Python product has its own `pyproject.toml` and `uv.lock`** — there is no workspace-level dependency declaration.
- **Dependencies are pinned via `uv.lock` and installed with `uv sync --frozen`** — enforced by `mk/python.mk`, which is included by every Python product's `Makefile`.
- **Runtime dependencies use broad lower bounds with tight upper bounds** (e.g. `>=X,<Y+1`) to allow patch/minor upgrades while blocking breaking changes — observed consistently across all eight `pyproject.toml` files.
- **`requires-python = ">=3.11"`** is declared in every Python product; the shared base image uses `PYTHON_VERSION=3.12` (from `mk/defaults.mk`).
- **Build system is pinned**: `[build-system] requires = ["uv_build>=0.8.14,<0.9.0"]` with `build-backend = "uv_build"` in every product.
- **Dev dependencies are isolated** under `[dependency-groups].dev` (pytest, jsonschema) and are not part of the runtime image.
- **OpenTelemetry instrumentation is standardized**: every Python service depends on `opentelemetry-exporter-otlp-proto-http`, `opentelemetry-instrumentation-fastapi`, `opentelemetry-instrumentation-httpx`, `opentelemetry-instrumentation-logging`, and `opentelemetry-sdk`.
- **Prometheus metrics use `prometheus-client` directly** (not `prometheus-fastapi-instrumentator`) — documented as a deviation in SPEC-005 due to incompatibility with the pinned starlette.
- **Node.js dependencies use caret ranges** in `package.json`; `node_modules/` is gitignored.
- **Platform version lockstep is enforced**: `make validate-version` (via `shared/shared-contracts/scripts/validate_version.py`) asserts that `VERSION`, every product's `pyproject.toml` version, and every service's `metadata.py` `SERVICE_VERSION` agree — this is a hard check in `make verify`.
- **Base image reproducibility is enforced**: `make base-images` builds `shared/base-images/base-uv` with `UV_VERSION=0.12.1` and `PYTHON_VERSION=3.12` from `mk/defaults.mk`; these values are overridable via `BASE_UV_UV_VERSION` and `BASE_UV_PYTHON_VERSION`.
- **Container images use a coordinated tag** derived from `VERSION` + git SHA (+ optional profile/dirty marker), computed once by the root `Makefile` and reused across all product images and the `.images.env` state file.
